# Fame Codex v5.0.9

This release reduces repeated Markdown block-matching work during ChatGPT Web streaming.

## Improvements

- Replace repeated linear searches of committed blocks with indexes for source ranges, keys, and unambiguous tag/text matches.
- Retain the latest committed ranged block instead of allocating and scanning a filtered array on each observation.
- Group source indexes by tag to avoid allocating a separate Map for every block.
- Preserve earliest-match behavior, rejection of rewritten/reordered committed text, semantic ambiguity checks, and virtualized-prefix handling.
- Add seven regression tests and a reproducible local benchmark: `bun run scripts/benchmark-markdown-reconciliation.ts`.

## Measured performance

Synthetic repeated-observation benchmark, excluding initial HTML conversion:

| Committed blocks | v5.0.8 | v5.0.9 |
| --- | --- | --- |
| 1,000 | 1.78 ms | 0.034 ms |
| 3,000 | 18.81 ms | 0.082 ms |

These results measure only block reconciliation, not whole-application speed or CPU/RAM savings. Indexes add memory proportional to committed block count. Pending-block fallback searches are unchanged.

## Compatibility and validation

- No changes to polling intervals, model selection, tool protocol, tab retention, concurrency, or Markdown stability timing.
- Local validation: 161 tests passed across focused and broader runs; TypeScript checking passed.
- Broader validation was not fully green: the Bigger Context mixed-density test timed out at 20 seconds, including an isolated rerun. A full harness run stalled during broker invocation and was stopped; the selected Markdown/completion harness tests passed.
- Live account/browser validation and whole-application resource measurements have not been completed. This release does not claim exhaustive behavioral parity or reduced total RAM usage.

Release installers and checksums are produced by the existing multi-platform release workflow.
