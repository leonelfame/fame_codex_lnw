# Fame Codex v5.0.10-alpha.1

This prerelease repairs unchanged interrupt hooks during explicit Install/Reinstall and fixes their execution through PowerShell on Windows.

## Fixes

- Reinstall can recover a uniquely identified hook after its position changes, ownership comments disappear, or TOML formatting changes, including journals from the older Fame launcher.
- Recovery verifies the command, hook settings, trust hash and complete remaining TOML document. Changed commands, added behavior, duplicate hooks and conflicting trust entries still stop installation with an explanation.
- Before a repair writes configuration, it saves the current config and both installation journals under the bridge home's `codex/repair-backups/` directory. Preflight does not create this backup or modify the config.
- Windows hooks now use PowerShell's call operator and literal argument quoting. Native Codex previously discovered and trusted the generated hook but its cmd-style command failed when executed by PowerShell.
- Refresh catalog and relocated-runtime smoke expectations for the current Astra capability, native model roster and Fame service name.

## Validation

- 55 hook and integration tests passed, including symlink preservation, line endings, unrelated settings, backup contents, rejected unsafe repairs and install/uninstall behavior.
- Native Codex catalog and interrupt lifecycle smoke tests passed on Windows. The latter confirmed cancellation of both the HTTP request and retained browser-turn fixture.
- A repaired local config was independently read by native Codex: exactly one matching hook, trusted status and matching hash.
- Runtime and launcher TypeScript checks, renderer build and relocatable runtime smoke passed on an isolated copy containing only this release's changes. Dependency audits reported no vulnerabilities.
- The broader runtime suite reported 698 passed and 13 failed. All 13 failure names also reproduced on the unmodified v5.0.9 baseline (694 passed, 14 failed, including an additional timeout). These include stale DEV/browser-partition fixtures and a Bigger Context timeout; the suite is not fully green.
- The launcher suite did not finish: a supervisor test failed under the sandbox and a test process remained running. The failing initial-health-cleanup test passed when rerun in isolation outside the sandbox. This is not a full launcher-suite pass.

## Prerelease limitations and recovery

Authenticated ChatGPT turns, Full-mode account tools, Voice, compaction and interactive upgrade flows have not been revalidated across Windows and macOS for this candidate. Native interrupt smoke uses a controlled browser-turn fixture, not an authenticated browser conversation. This candidate therefore remains an alpha under the repository's release-validation policy.

After installing this candidate, keep the launcher open, choose Install/Reinstall, then fully quit and reopen Codex to refresh its model picker. If recovery refuses a changed or ambiguous hook, compare `config.toml` with the installation journal rather than deleting another hook or its trust settings. Pre-repair files are retained in `codex/repair-backups/`; restore the config and both journal files together if reverting that repair. Users who do not want a prerelease can remain on v5.0.9.

The release workflow builds platform installers and publishes their checksums. No unrelated in-progress launcher localization edits are included.
